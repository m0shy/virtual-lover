# 语音合成（GPT-SoVITS）指南

> 本文为操作教程，行文中的"你"指部署者本人。

让 AI 用你训练的音色「开口说话」。整体分两步：**训练音色**（一次性）+ **启动推理服务**（日常）。

先交代几个本文反复出现的名词：**GPT-SoVITS** 是开源的声音克隆/语音合成项目；**GSVI**（GPT-SoVITS-Inference）是把它的推理包成 HTTP 服务的整合包（第 0 节下载的就是它）；**Huohua** 与 **Hutao** 是语音包里的两个音色注册名（Huohua 注册了 7 种情绪，Hutao 只有单情绪，框架默认音色已切到 Huohua）；文中 R1-R9、O 编号是本项目的内部修缮轮次与任务编号（定义见 PERF_SPEC / VOICE_SPEC）。

## 0. 前置：下载推理包（目录名是硬性约定！）

本项目推荐使用 GSVI（GPT-SoVITS-Inference）推理整合包：

- 下载地址（任选其一）：
  - GitHub：https://github.com/X-T-E-R/GPT-SoVITS-Inference
  - Gitee（国内快）：https://gitee.com/xxoy/GPT-SoVITS-Inference
- 解压到仓库根目录，**必须把解压出的目录重命名为 `voice-engine`**——框架按这个名字探测语音包（`vl.toml` 的 `[tts].gsvi_root`），名字不对会被静默跳过
- 目录改名后仍为上游原版（MIT © 2024 RVC-Boss），本项目**不修改、不分发**其内容——仅按上游 LICENSE 保留原样本地使用；推理服务经 `scripts/voice_engine_entry.py`（vl 自有 wrapper）启动，该 wrapper 不属于上游
- 若用官方 GPT-SoVITS 仓库：训练用它，推理服务仍建议用 GSVI（下文的对接方式针对它的 `/tts` 接口）

## 1. 训练你自己的音色（约 30~60 分钟）

1. 准备 1~10 分钟目标音色的干净人声（无 BGM、无混响）
2. 用官方 [GPT-SoVITS](https://github.com/RVC-Boss/GPT-SoVITS) 的 WebUI：
   - 1A 数据集格式化（自动切分 + ASR 标注）
   - 1B 微调 SoVITS 模型、1C 微调 GPT 模型（各 5~10 epoch 即可）
3. 产出两个文件：`GPT_weightsxxx/xxx.ckpt` 与 `SoVITS_weightsxxx/xxx.pth`
4. 放入语音引擎包的 `trained/<角色名>/` 目录，并在 `trained/character_info.json` 注册：

```json
{
  "deflaut_character": "你的角色名",
  "characters_and_emotions": {
    "你的角色名": ["default"]
  }
}
```

> ⚠️ 伦理与合规：只克隆你有权使用的音色（自己、授权声优、公开发布的合成音）。训练产物仅自用，请勿公开分发模型文件。

## 2. 启动推理服务（日常）

**v2 起你通常不需要手动启动它**：新栈框架默认 `tts.auto_start=true`，进程起来后会自动拉起语音引擎（详见第 3 节）。以下手动方式仍然可用——框架采用「收编优先」策略（收编＝检测到端口已有实例就直接接管使用，而不是另起一个）：端口 5000 已有应答时直接收编现有实例，**绝不杀你手动开的服务**：

- 双击 `voice-engine\0 一键启动脚本\5 启动后端程序.bat`；或什么都不做，交给框架自动拉起
- 看到 `Running on ...` 即成功（模型加载约 1~2 分钟；框架自动拉起时热启动约 15 秒即可开口，冷启动最长 2 分钟；手动 bat 直启上游脚本时监听 `0.0.0.0`，框架拉起时只绑 `127.0.0.1`，见第 5 节）
- 自检：浏览器打开 `http://127.0.0.1:5000/character_list` 能看到角色列表

## 3. v2 框架接入（一次性，迁移时已自动完成）

v2 中语音不再是 AstrBot 面板里的一个 provider，而是框架内建的 `voice/` 模块。接入状态全部落在 `local/config/vl.toml` 的 `[tts]` 段：

```toml
[tts]
enabled = true                # 语音总开关（false=整条语音链路旁路，纯文字）
base_url = "http://127.0.0.1:5000"   # 必须本机直连；旧配置里的 host.docker.internal 残留会在加载时归一化
character = "Huohua"          # 默认音色（须与 /character_list 注册名一致，英文大小写不敏感）
emotion = ""                  # 兜底情绪（情绪联动未命中时的第二跳，见下）
auto_start = true             # 框架自动拉起语音引擎（false=完全手动，见第 2 节）
text_lang = "zh"
trigger_probability = 1.0     # 每条回复带语音的概率（0~1，控制台语音页有滑杆，改了立即生效）
```

**语音和文字怎么共存**：主聊天回复永远是「文字先发、语音随后附加」的双轨——她说的话
你一定看得到文字，主管线没有「只发语音」的路径（R3 终裁）。主动消息侧才有这个开关
（`[proactive].always_send_text`）：`false` = 主动消息合成成功时只发语音；`true` = 语音
文字都发。旧版的 `[tts].always_send_text` 是死键，已删除（R5）——想让日常聊天少发点
语音，用 `trigger_probability`（每条回复独立抽样）。

框架替你做的事（都有对应日志，出了问题先看 `local/logs/vl.log`）：

1. **自动拉起与自愈**（`tts.auto_start=true` 时）：以固定 argv 启动
   `voice-engine\runtime\python.exe scripts\voice_engine_entry.py`（vl 自有 wrapper，
   只绑本机回环 127.0.0.1，无窗口），输出落 `local/vl_data/logs/voice-engine.log`，
   PID 记在 `local/vl_data/voice/voice-engine.pid`。
   就绪预算 5 分钟（热启约 15 秒）；崩溃自动重启，连续判死进入熔断冷却，恢复后自动回语音。
   你手动先启动的实例只会被收编，不会被杀。
2. **情绪联动**：她的心情（开心/难过/生气/害羞/孤单/平静/兴奋 7 态）按映射表换算成音色的注册情绪
   （默认表：开心/害羞/兴奋→傻白甜、生气→疯批、难过→慢速病娇、孤单→平常的、平静→聊天；
   箭头右侧这些名字是音色包里注册的情绪标识，不是心情词）。
   映射值不在音色注册表里时自动回退 `emotion` → `default`，**绝不发非法情绪**（上游引擎对未注册情绪
   是静默忽略的，不报错——客户端必须自己拦）。
   > R3 按听感实测重排：calm 是常态（一天里几乎全是它），旧映射把它配给偏冷御姐的「平静的」，
   > 已改「聊天」；害羞/兴奋改配「傻白甜」（疯批调只留给生气）。控制台映射表卡可随时再调。
3. **语音清洗**：每段合成前自动剥掉 emoji/颜文字/正则碎片残留——这些念出来是灾难；
   清洗后为空的段直接跳过（宁可不念这段，也不念一串乱码）。
4. **语音缓存**：同一句话（含角色/情绪等全部请求参数）只合成一次，之后秒回；缓存在
   `local/vl_data/voice_cache`，**属可再生数据，不进备份**（备份清单已排除）。
5. **管理控制台「语音」页**：状态卡（引擎状态/当前音色/注册情绪/缓存占用/PID + 语音触发
   概率滑杆——运行时立即生效并写回 vl.toml）、试听卡（任意文本+注册情绪下拉试听，
   default 不在列——它是「无情绪」兜底值不是可试听的情绪）、映射表卡（7 行映射可改、
   行内试听、保存即热加载）、启停卡（启停语音后端、看 voice-engine.log 最近日志）。

> ⚠️ `base_url` 就写 `http://127.0.0.1:5000`。旧文档让你填 `host.docker.internal` 是 v1 容器时代的
> 写法——v2 框架跑在宿主机上，同机直连即可；这个残留地址在 v2 里是必炸配置（启动时会归一化并告警）。

## 4. 验证与排障

| 症状 | 检查 |
|---|---|
| 语音不发声 | 控制台「语音」页状态卡：引擎是否就绪（冷启 15 秒内显示 starting 属正常，不是故障）→ `tts.enabled` 是否为 true → `local/logs/vl.log` 里 TTS/voice 相关告警（合成失败自动回退纯文字，聊天不受影响） |
| 引擎一直 starting | 看 `local/vl_data/logs/voice-engine.log`：模型加载报错（显存不足/模型文件缺失最常见）；或 5000 被别的程序占了 |
| 角色不存在 | `tts.character` 与 `http://127.0.0.1:5000/character_list` 的注册名一致（英文大小写不敏感；中文情绪名要与注册情绪逐字一致） |
| 某种心情没有对应声音 | 映射表里该行在控制台被标黄=映射值不在音色注册表（联动不会生效），改映射或换多情绪音色 |
| 重复的话还是要等合成 | 缓存未命中才会慢；确认 `local/vl_data/voice_cache` 可写（缓存写入失败只告警不阻塞） |
| 合成慢 | 首句慢属正常（模型冷启动）；持续慢检查是否用了 CPU（voice-engine.log 应有 cuda 字样） |

## 5. 安全提示：监听面取决于启动方式，且 v2 下它常驻后台

这一节的事实值得单独说清：

1. **监听面分两条路**（R8 起）：
   - **框架自动拉起**（`tts.auto_start=true` 默认）：经 vl 自有 wrapper
     （`scripts/voice_engine_entry.py`）启动，只绑 `127.0.0.1:5000` 本机回环，
     局域网设备**不可达**；
   - **手动双击 `voice-engine\0 一键启动脚本\5 启动后端程序.bat`**：直启上游
     `tts_backend.py`，其 `__main__` 硬编码 `host='0.0.0.0'`，且 `Inference/config.json`
     的 `enable_auth` 默认 false（均为上游行为，本项目不改上游源码）——同一局域网
     内的设备理论上也能调用你训练的音色合成**任意文本**（语音冒用风险）。
     两种路径下鉴权默认都是关的：wrapper 只解决局域网暴露面，本机其他本地账户
     理论上仍可达（介意可改 `Inference/config.json` 开 `enable_auth`）。
2. **v2 框架默认把它拉起后常驻**（`tts.auto_start=true`）：v1 时代"关掉那个窗口就关了语音"的
   直觉失效——框架崩溃自愈会把它拉回来，重启 vl 进程它也会自动回来。框架启动日志会在拉起时
   明确说明监听面。

处置建议：

- **家用网络 + 框架自动拉起**：仅回环监听，风险较低，可保持默认（方便）。
- **公共 Wi-Fi / 宿舍网**：不要用手动 bat 直启；在控制台「语音」页用启停卡停掉
  引擎，或把 `vl.toml` 的 `tts.auto_start` 改为 `false`（永久改为手动启动）；
  也可整段 `tts.enabled=false`。
- 停止请用 `一键停止.bat`（按 PID+命令行核验精确结束，无残留窗口）或控制台启停卡，
  不要去任务管理器碰运气。
- 若你确需手动 bat 直启（监听 0.0.0.0），建议加防火墙规则封 5000 入站——v2 下
  只有宿主机进程调用它，封入站不影响本机 127.0.0.1 回环。

## 6. 与本地大脑共存：开关入口与管理边界（五轮修缮 + R9）

本地大脑（llama.cpp，任意 GGUF 模型，默认 `127.0.0.1:8002`）与语音引擎（5000）是两个互不隶属的
可选宿主机进程，但可能共用同一块显卡——三个管理动作的边界值得说清。
三个大脑双击脚本已撤（R9），等价入口收进管理控制台「引擎与人格」页与 QQ 聊天命令：

| 管理动作（在哪点） | 动什么 | 不动什么 |
|---|---|---|
| 「切到本地大脑」（控制台「引擎与人格」页；QQ 里 `/brain local`） | 起 8002 llama-server + 把 vl.toml `[chat]` 切到本地 + 重启 vl（云端原配置自动备份 `vl.toml.cloud-backup`；首次运行自动 GGUF 转换+量化） | `[tts]` 段与语音引擎进程原样，语音照常 |
| 「只停本地引擎」（控制台「引擎与人格」页 ghost 按钮，即 `scripts/brain_switch.py stop`） | 只停 8002 服务进程 | vl.toml 不改——配置仍指本地时她会暂时失声，重启 8002 或切回云端即恢复 |
| 「切回云端大脑」（控制台「引擎与人格」页；QQ 里 `/brain cloud`） | 恢复云端 `[chat]` 配置 + 重启 vl + 停 8002 | 语音不受影响 |

三点共存须知：

1. **显存预算**：本地大脑全载约占 5.8G 显存（Q4_K_M + KV q8_0，8GB 卡实测口径，
   见 `scripts/brain_switch.py` 的 LLAMA_ARGS 注释），语音合成同样吃显存——小显卡
   两者同开，语音可能变慢或显存不足（语音引擎日志出现 cuda OOM 字样）。让路方式：
   控制台「只停本地引擎」临时停 8002，或 `一键停止.bat` 全停（它连语音引擎一起停）。
2. **启停联动**：`一键启动.bat` 按 vl.toml 自动联动——指本地时自动带起 8002（看护
   30s 探活、判死自动重拉），指云端时不碰 8002；语音引擎仍按 `[tts].auto_start`
   （默认 true）由 vl 首次开口自动拉起，与大脑选本地还是云端无关。
3. **排障归属**：语音问题看 `local/vl_data/logs/voice-engine.log`（第 4 节排障表），
   本地大脑问题看 `local/vl_data/logs/brain-local.log`——两本账别看串。

## 7. 晚安语音配方：让她主动说晚安（R9，纯配置不做独立功能）

想要她每晚睡前来一句带语音的晚安？不需要新功能，`[proactive]` 主动消息 +
语音双轨（合成成功只发语音、失败自动回退文字）现成就能拼出来：

```toml
# local/config/vl.toml —— 晚安语音配方（改完重启 vl 生效）
[proactive]
enable = true                 # 主动消息总开关（晚安/纪念日仪式感都走这条通道）
tts_enabled = true            # 主动消息走语音双轨：合成成功只发语音（dual_send 接缝）
always_send_text = false      # false=只发语音；true=语音+文字都发（想留字据就开）
quiet_hours = "23-7"          # 安静时段：23 点后她不再打扰——晚安要赶在这之前
min_interval_minutes = 30
max_interval_minutes = 120
prompt_template = """[系统任务：主动对话] 现在是 {{current_time}}。
如果现在已入夜（21 点以后），用一两句温柔的话跟他说晚安，语气符合你的人设，
不要提任何系统任务字样；其他时段就正常找他聊一句近况。"""

[tts]
enabled = true                # 语音总开关必须开，合成才有产出
base_url = "http://127.0.0.1:5000"
auto_start = true
```

生效链路与注意事项：

1. **双轨语义**（`tts_enabled=true` 时）：晚安这句话先走语音合成，合成成功**只发语音**；
   引擎未就绪/合成失败/发送失败时自动回退纯文字——「她想说的话」不会因为语音故障
   而消失（`soul/proactive.py` 行为⑧的 `dual_send` 接缝，与主动消息全链路共用）。
2. **时间窗**：主动消息按 `min/max_interval_minutes` 随机触发、`quiet_hours` 内一律
   跳过并重排——模板里已让 LLM 按「入夜后说晚安、其余时间聊近况」分流，不需要为
   晚安单开一条通道；想要更准点的晚安，把触发区间收窄（如 30-45 分钟）即可。
3. **不想让她白天主动打扰**：把 `min/max_interval_minutes` 拉大（如 240-480），
   并在模板里写明「白天不要发消息，只在入夜后说晚安」。
4. **验收**：QQ 里收到语音晚安即配方成立；合成失败时会收到同内容的文字（同时
   `local/logs/vl.log` 有 `TTS 合成异常，回退纯文字` 记录）。触发概率、音色与情绪
   映射都在控制台「语音」页调整。
5. **纪念日仪式感**（R9 同源）：`[proactive]` 新增 `anniversary` 开关（默认关）——
   开启后她以「你们认识第一天」（会话库最早一条消息）为锚点，在第 7/30/100 天各
   主动送一次纪念日消息，同样走上面的语音双轨。详见 `virtuallover/soul/anniversary.py`。
