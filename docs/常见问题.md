# 常见问题（FAQ，v2）

架构一句话：她的全部都在宿主机 `virtuallover` 单进程里（大脑+控制台），QQ 协议端（实际登录 QQ 号、收发消息的组件）是 napcat 容器（NapCat 是第三方 QQ 协议端，compose 里服务名 `heart`、容器名 `vl-heart`）——所以"看日志""改配置""重启"的对象都和旧版多容器编排不同。文中 vl 指本项目的 `virtuallover` 主进程，v2 指现行架构（v1 是旧的五容器编排）。

**Q：控制台密码在哪？**
`local/console.json` 的 `password` 字段（首次启动随机生成、明文存放——该目录已 git 忽略且仅本机可读；同一次启动也会打印到 `local/logs/vl.log`，搜「控制台密码」）。忘了就删掉 `local/console.json` 重启 vl（`一键停止.bat` → `一键启动.bat`），会生成新密码。控制台只绑本机 127.0.0.1:8787。

**Q：日志在哪？**
- `local/logs/vl.log`（+ `.log.1`~`.log.3` 轮转）——主日志，排障先看这里
- `local/vl_data/vl_runtime.log`——vl 主进程的启动/崩溃输出（看护守护拉起记录也在这）
- `local/vl_data/logs/brain-local.log`——本地大脑 llama-server
- napcat 容器：`docker logs vl-heart --tail 100`

**Q：本地大脑怎么开/关？**
管理控制台「引擎与人格」页（http://127.0.0.1:8787）：「切到本地大脑」（起 8002 llama-server 并把 vl.toml 切到本地）、「只停本地引擎」（只停服务，不改配置）、「切回云端大脑」（恢复云端配置）。QQ 里也可用 `/brain local|cloud`（管理员）。`一键启动.bat` 会按 vl.toml 当前配置自动联动：配的是本地大脑就自动带起 8002。模型文件与转换要求见 `scripts/brain_switch.py` 头注释。

**Q：云端欠费/Key 失效，她会哑吗？**
看配置。智能降级开启（`vl.toml` 的 `[chat] fallback_enabled=true`，且本地大脑可用）时**不会**：ark 欠费这类 401/403「不可重试」故障连续 2 轮，她自动黏性切到本地大脑保命（黏性＝切过去后稳住，不随每条消息来回摆；8002 没起就按需拉起）并打显著告警，之后直发本地、不再空耗云端重试；半开探针每 30 分钟探一次云端（探针＝降级术语里对"曾判死通道的周期性轻量重试"），恢复后只提示「可用 /brain cloud 切回」——**绝不自动替你切回扣费**（恢复后的计费裁决留给你）。普通的瞬态故障（5xx/超时）只做单次兜底，下一轮仍先试云端。智能降级未开（默认关）或没装本地大脑时她会哑——但错误会进 `local/logs/vl.log` 和控制台「最近事件」面板，不会再出现「控制台全绿她却沉默」的假象；聊天里 `/brain` 随时看大脑状态。

**Q：语音地址/语音不发声？**
语音后端是宿主机 GSVI 进程，地址统一写 `http://127.0.0.1:5000`（vl 会自动把旧的 `host.docker.internal`/`localhost` 残留归一化成 127.0.0.1；控制台语音页有一键修正按钮）。排障表见 `docs/语音.md`：核心三点——控制台语音页开关打开、5000 端口有应答（HTTP 000=未启动，首次开口自动拉起约 15 秒）、`docs/语音.md` 第 0 节的语音包已下载。

**Q：私聊机器人不回复？**
按顺序排查：
1. 控制台「QQ 登录」页看她是否在线（掉线就重新扫码；协议端 WebUI 61990 仅备查（compose 中性端口，宿主侧 61990→容器 6099））
2. `local/logs/vl.log` 有无你这条消息的记录——没有就是协议端反向 WS 没连上（全新安装由 setup.bat 自动配置；手动装的话检查 `local/napcat_config/onebot11_<QQ>.json` 的 `url` 应为 `ws://host.docker.internal:6199/ws`，改后 `docker compose restart heart`）
3. 日志里有 `LLM 调用最终失败` = Key/额度/网络问题（去控制台配置页核对 Key 与端点）
4. 你不在 `vl.toml` 的 `whitelist`/`admins` 里——setup 安装时若填了主人常用 QQ 会把它加进 `whitelist`（跳过则只放行小号自己）；把你的常用 QQ 补进顶层 `whitelist` 与 `admins` 后重启

**Q：QQ 掉线 / 每次重启都要扫码？**
QQ 登录态保存在 `local/napcat_data`，正常可保持长期在线。频繁掉线多为：异地登录挤下线、长时间不活动、或腾讯风控。缓解：用独立小号、降低主动消息频率、保持容器常开。

**Q：她不记得我说过的话？**
记忆功能依赖单独的 Embedding 配置（Embedding＝把文本转成向量，供记忆检索用）：安装时若选了「跳过」，`vl.toml` 里 `[embedding] enabled=false`＝记忆暂闭（聊天正常）。补齐 `[embedding]` 的 `enabled=true` + 端点/Key/模型后重启即可。已启用还不记：记忆是每 N 轮对话才后台总结入库（不是每句都存），且相似度低于阈值的不注入——`/eval memory` 可量化检查。

**Q：怎么备份/搬家？**
备份：`scripts/backup.bat`（自动先停容器保一致）。搬家：新机器装 Docker Desktop → 拷贝整个目录（含 `local/`）→ 双击 `setup.bat`（已有配置自动跳过交互）→ 控制台重新扫码。

**Q：`docker compose down` 会丢数据吗？**
不会。你的数据全在 `local/`（宿主机目录），down 只删容器；napcat 的框架配置与登录数据也已挂载持久化，`一键启动.bat` 一键全回来。

**Q：Windows 防火墙弹窗要不要允许？**
弹窗来自 Docker Desktop / python 绑定端口。默认所有端口只绑 127.0.0.1，勾不勾都不影响本机使用。

**Q：端口占用启动失败（6199/8787）？**
`netstat -ano | findstr 6199`（或 8787）找占用进程。8787 多半是上一个 vl 没退干净：`一键停止.bat` 后再启动；6199 是 vl 自己的桥端口，同上。

**Q：想让她只跟我一个人聊？**
`vl.toml` 的 `whitelist` 就是门禁名单（门禁 = `whitelist` ∪ `admins`，白名单外的消息直接忽略）——把你的常用 QQ 加进顶层 `whitelist` 她才回你；再加进 `admins` 还能使用命令与控制台全部动作。改完重启 vl 生效。
