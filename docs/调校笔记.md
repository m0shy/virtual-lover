# 调校笔记：这套系统的参数为什么这样取

> 本笔记记录 `deploy/cmd_config.example.json` 与各插件配置中关键参数的**设计依据与调整思路**。
> 这些值来自我数月真实运行的迭代取舍——值本身在配置文件里，为什么是这个值在这里。
> 背景交代：这批参数成文于 v1 时代（当时以 AstrBot——一个开源机器人框架——为大脑、
> 五容器编排运行）；v2 迁移时，对话/记忆/语音/主动消息等行为参数已按 SPEC §11.1 带入
> `local/config/vl.toml`，取舍逻辑仍然适用；第 9 节容器编排侧条目的现状以
> `docker-compose.yml` 与 [docs/部署详解.md](部署详解.md) 为准。
> 面向两类读者：想微调自己体验的读者、想理解设计权衡的工程师。
> 名词速览：**风控**＝平台对机器人账号的检测与限制；**stall**＝限流时排队放行（相对的
> drop 是直接丢弃）；**fail-closed**＝白名单开而名单为空时默认拒绝所有人；**mnemosyne**
> ＝v1 的长期记忆插件名；**t2i**＝文字转图片；**τ=4h**＝指数衰减的时间常数（约每 4 小时
> 情绪强度衰减到 37%）；**prompt 缓存**＝服务商对重复请求前缀给出的缓存计费。

## 1. 频率与风控（platform_settings）

| 参数 | 值 | 依据 |
|---|---|---|
| `rate_limit` | 30 秒 10 条，`strategy: stall` | QQ 对非官方协议的风控核心看**消息频率**。30s/10 条是长期运行未触发风控的经验上限。关键在 stall（排队放行）而非 drop（丢弃）：机器人被限流时回复会迟到但不会消失——对话体验上"她打字慢了"远好于"她不理你了" |
| `friend_message_needs_wake_prefix` | false | 伴侣场景私聊免唤醒词（不用喊名字/斜杠才理你）；群里才用 `/` 前缀——既保私聊亲密感又防群里被误触 |

**怎么调**：如果账号被冻结/警告，第一动作是把 count 降到 5 以下、拉长 interval；如果完全不在意风控（小号随便死），可以放宽到 15 条。

## 2. 真人感分段回复（segmented_reply）

| 参数 | 值 | 依据 |
|---|---|---|
| `interval_method` | random | 固定间隔（如恒定 2s）在时间轴上完全等距，一眼机器。随机化是最便宜的拟真 |
| `interval` | 1.5~3.5 秒 | 区间下限不能太低（刷屏感+风控敏感），上限不能太高（等她说话等到烦）。1.5~3.5 是"人在打字"的自然节奏带 |
| `split_mode` + `regex` | 按 。？！~… 切句 | 人的消息以"一句"为单位发送，LLM 却习惯一次输出整段。按句尾标点切分还原成人的粒度 |
| `words_count_threshold` | 100 字 | 短回复（<100 字）不值得切分——一条发完更像随手回；长回复才切成连发 |

**怎么调**：想要更"急性子"就缩小区间（0.8~2.0）；想要更"慢热温柔"就放大（2.5~6.0）并降低 threshold 让短句也连发。

## 3. 主动消息（proactive_chat）

| 参数 | 值 | 依据 |
|---|---|---|
| 调度区间 | 30~120 分钟随机 | 固定间隔的"每 60 分钟来找你"三天就会被识破；随机区间让主动行为不可预测，拟真且降低风控特征 |
| `auto_trigger_after_minutes` | 30 | 静默半小时即重建任务——覆盖"聊着聊着断了"的场景，她会在管理员离开半小时后自然地追问 |
| `quiet_hours` | 23:00–7:00 | 免打扰是底线体验：半夜被 bot 吵醒一次就会想卸载 |
| `max_unanswered_times` | 3 | 连续 3 次不回自动停：模拟"人被晾久了也会生气/放弃"，同时防止对已离线者无限轰炸（风控+体验双保险） |
| 主动 prompt | 含 `{{unanswered_count}}` 变量 | 未回次数进提示词，让语气随被晾次数产生细微变化（失落/困惑）——情绪连续性是拟真的关键细节 |

**怎么调**：热恋期缩到 15~60 分钟；嫌烦放大到 120~360 并把 max_unanswered 降到 2。

## 4. 隐私与边界

| 参数 | 值 | 依据 |
|---|---|---|
| `id_whitelist` 开 + 空名单 + 管理员豁免 | — | fail-closed 设计：白名单开启而名单为空时**默认拒绝所有人**，仅管理员（我自己）豁免。效果=只有我能跟她聊，且不需要维护名单。改配置失误的最坏结果是"她不理任何人"而非"她理了陌生人"——安全侧倒 |
| `t2i_word_threshold` | 150 字 | 超过 150 字的长回复转图片，避免 QQ 长文刷屏的观感断层 |

## 5. 长期记忆（mnemosyne）

| 参数 | 值 | 依据 |
|---|---|---|
| `num_pairs` | 2（轮） | 每 2 轮对话总结一次入库。太稀（如默认 5）会漏掉细节；太密（1）总结请求本身成为主要 token 开销且碎片化 |
| `top_k` | 2 | 每次检索注入 2 条最相关记忆。注入过多会挤占上下文并让回复"刻意引用过去"，2 条是"自然想起"的感觉 |
| 注入方式 | on_llm_request 追加 system prompt，而非改写 system prompt | 注意成本权衡：AstrBot 官方文档警告每轮变化的内容追加进 system_prompt 会破坏 LLM 的 prompt 缓存（成本可放大数倍）。本引擎接受该取舍（状态量小、注入文本短）；若本地 API 按 prompt 缓存计价敏感，可关闭 inject_enabled 或改为低频注入。记忆是"她想起来的事"，不是"她的人设"——语义位置区分 |

**怎么调**：记忆"记不住小事"→ num_pairs 降 1；回复老翻旧账 → top_k 降 1。

## 6. 情绪引擎（vl_mood_engine）

情绪层与全系统共享同一条元原则——**消除确定性**（文末「通用调参心法」）；在此之上另有两条自守边界：**状态是修辞的 nudge 而非对话本身**（nudge＝只轻轻推动语气，不进入对话内容）——内心状态只注入 system prompt 影响语气，绝不进入回复正文、绝不说出数字；**规则分类的可审计性优先于语义精度**——关键词正则而非 LLM 判定事件，每条消息归入哪类可复现、可单测、可配置扩展，分类偶尔错一次无妨，不可解释才是灾难。

| 机制 | 设计依据 |
|---|---|
| 否定窗口 | 负面词扣分后进入短窗冷却，窗内重复负面语不再叠加扣分——一次口角只伤一次，刷屏骂刷不穿好感 |
| 每日计分上限 | 单日好感增量封顶——热恋期狂聊也无法一天刷满，关系温度按天演化才像真人 |
| 读时时间衰减 τ=4h | 注入 system prompt 前按 τ=4h 指数衰减心情强度——情绪自然回落，无需后台定时器 |
| 危机词不落井下石 | 命中危机类词汇（求助/自我伤害倾向）时暂停扣分降温——她绝不对求助的人摆脸色，关怀交给安全话术 |

## 7. 语音（gsv_tts_selfhost）

| 参数 | 值 | 依据 |
|---|---|---|
| `dual_output` | true（文字+语音同发） | 语音后端是宿主机进程，可能挂/慢。双发=容灾：语音失败至少文字还在，而且 QQ 语音条+文字的观感本就更像真人 |
| `timeout` | 60s | 首次合成含模型冷启动可达 30s+，默认 20s 会误判失败 |
| 适配器类型 | `gsv_tts_selfhost` | 血泪坑：`gsvi_tts_api` 调用的 `/infer_single` 端点 GSVI 推理包**不存在**，404 后 AstrBot 静默回退纯文字——表现为"配置全对但语音永远不响"。详见 docs/语音.md 的避坑说明 |

## 8. 表情包（meme_manager）

| 参数 | 值 | 依据 |
|---|---|---|
| `emotions_probability` | 60% | 每条都发表情=表情包复读机；从不发=冷冰冰。60% 是"偶尔发表情"的真人频率 |
| `max_emotions_per_message` | 1 | 一条消息最多 1 张：连发多张表情更像营销号 |

## 9. 基础设施侧

| 参数 | 值 | 依据 |
|---|---|---|
| 日志轮转 | 10MB × 3 份 | 7×24 常驻服务的磁盘上限：实测 milvus 高峰 ~240MB/天，无轮转数月即写满 C 盘。10m×3=单容器 30MB 封顶，五容器合计 <200MB |
| astrbot 镜像 | 钉 v4.28.2 | latest 的面板密码机制、配置结构跨版本会变（v4.25 前后完全不同）；钉版本=钉行为。升级走 scripts/update.bat（先备份） |
| Milvus 端口 | 不发布到宿主机 | mnemosyne 走容器网络 `milvus-standalone:19530` 直连；发布 19530 到局域网=把无认证的记忆库敞开，零收益纯风险 |
| napcat 挂 astrbot 插件目录（只读） | :ro | napcat 只需按路径读媒体文件来发送；可写挂载意味着 napcat 被攻破时可篡改 astrbot 插件数据——最小权限原则 |

---

**通用调参心法**：这套系统的所有"拟真"参数共享同一个原则——**消除确定性**（随机间隔、随机调度、概率表情、情绪变量）。机器感的本质是行为完全可预测；每引入一处受控随机，真实感就上一个台阶，同时天然降低平台风控的特征匹配。
