# 回退 SOP（v2 新栈 → v1 旧栈）

> **这是一份迁移期记录**：本文形成于 v1→v2 架构迁移期间（2026-10）。文中「14 天回退窗口」
> 是迁移完成时定下的观察期承诺；窗口内它是可操作的 SOP，窗口外本文件只剩考古价值
> （冻结语义见文末）。文首先交代两个说法：v1 是旧的五容器编排、v2 是现行单进程架构；
> O10/O14、R6 等是本项目的内部任务编号与修缮轮次编号（定义见 PERF_SPEC）。
> 它是 O10 收尾的产物（PERF_SPEC §4-O10 + §7.2）。适用窗口：v2 迁移完成后的 **14 天回退窗口**内。
> 回退演练由我实测：协议端指向回退 **17 秒**、整组回退 **4 分钟**（实操记录，2026-10-11）。
>
> ⚠ **R6 退役声明**：本机 AstrBot 镜像已清除（`docker images` 无 `soulter/astrbot`，
> 2026-10-13 实查），**档 B（整组回退）实质退役**——compose 的 legacy 组定义虽保留，
> 整组拉起会因镜像缺失而失败（三件套镜像仍在，档 A 三件套回退不受影响）。
> 指向回退（§1）仍然完全可用。
>
> 名词速览：**回退**＝从 v2 新栈退回 v1 旧栈继续服务；**档 A**＝只回退 Milvus 记忆
> 三件套（etcd＋minio＋milvus 三个容器，分别是元数据、对象存储与检索本体）的方案档位；
> **档 B**＝整组回退（含 AstrBot 大脑）的方案档位；**指向回退**＝只把 QQ 协议端的连接
> 目标改回旧栈、不动任何大脑。

## 0. 什么时候回退、回退什么

| 症状 | 回退档位 | 说明 |
|---|---|---|
| v2 大脑翻车（vl 进程起不来 / 回复质量灾难 / 桥连不通且修不好） | ~~档 B：整组回退~~（**已退役**：本机 AstrBot 镜像已清，见文首声明） | 修复 v2 本体或从备份恢复 vl_data |
| 仅记忆库需要旧栈（极端罕见：v2 内嵌向量库损坏且回退验证需要对照旧库） | **档 A：三件套回退**（etcd + minio + milvus） | 注意旧库是空库（见下），通常没有回退价值 |
| v2 大脑死了但协议端还指着新栈桥，QQ 消息无人应答 | 先做 **协议端指向回退**（17s，§1 仍可用） | 指向回退只恢复消息通路，不恢复大脑 |

**停机语义提醒（O10）**：旧 Milvus 库已实测为空库（证明存档
`backup/milvus_check_20261011205548.json`（未随仓库发布），1 个集合、总行数 0）。回退后她"想不起
旧事"不是故障——旧栈记忆本来就是空的，v2 的记忆在 `local/vl_data/` 内嵌向量库里，
旧栈读不到它。

## 1. 协议端指向回退（最先做，实测 17s）

协议端 `onebot11_*.json` 在每次指向切换时都有写前备份（`*.bak-<时间戳>`），
"回退"= 从最近备份恢复原文件。两个入口二选一：

- **vl 控制台**（vl 进程活着时）：控制台 → 服务控制 → `napcat_rollback` 动作
  （随 vl 同生死）；
- **独立 CLI**（vl 进程死了也能跑——workbench 退役后这不依赖任何活进程）：

  ```bash
  python -m virtuallover.tools.config_migrate --rollback-napcat
  # 可选 --restart-napcat：恢复后定点重启协议端容器（docker 不可用时会告警，
  # 文件恢复本体不受影响，退出码仍为 0）
  ```

  恢复结果：`onebot11_*.json` 回到最近一次指向切换前的原文（旧栈 url + 旧栈 token）。
  无备份（从未切换过）时退出码 1，文件不被触碰。

计时预算：恢复 + 定点重启 ≈ **17 秒**（我实测于 O10 收尾）。

## 2. 档 A：三件套回退（勿整组！）

只拉 Milvus 元数据/存储/检索三容器，**不要**用不带服务名的整组 up（那会把
astrbot 一起拉起来——注意档 B 已因镜像清除而退役，见文首声明）：

```bash
docker compose --profile legacy up -d etcd minio milvus
# 验证：docker compose --profile legacy ps —— milvus-standalone healthy 即就绪
# （首次健康门控串行等待，实测 3~4 分钟内）
```

需要重新做空库取证时同款姿势（override 取证流程，见
`virtuallover/tools/milvus_check.py` 模块 docstring）：三件套拉起 → 跑
`python -m virtuallover.tools.milvus_check` → `docker stop -t 60 milvus-standalone milvus-etcd milvus-minio` 停回。

## 3. 档 B：整组回退（v1 全家桶）

```bash
# 0) 停 v2 全家（保留窗口/数据，不要删 local/）：
一键停止.bat
#  （等价：python scripts\service.py stop——vl/看护/本地大脑(8002)/语音引擎/协议端全停；
#   PID+命令行双核验防 pid 复用误杀。协议端随后由整组 up 重新拉起）
# 1) 协议端指回旧栈（§1，17s）
# 2) 起旧栈整组（含 astrbot 大脑 + 三件套）：
docker compose --profile legacy up -d
# 3) 等待：milvus healthy → astrbot 起（容器内插件依赖已在，无需重装）：
docker compose --profile legacy ps
# 4) 验证：AstrBot 面板 http://127.0.0.1:6185 可登录 + QQ 发消息她回复
```

计时预算：up + 健康门控串行等待 ≈ **4 分钟**（实测口径 17s-4min 的上限）。

## 4. 停止纪律：一律 `stop`，`-t 60` 优雅

- **回退演练/日常验证后停回旧栈**：`docker stop -t 60 <容器名>`（给容器内
  SQLite/存储引擎 60 秒落盘刷盘，`-t 60` 是演练实测不杀进程的宽限值）；
- **绝不用 `compose down` 做回退收尾**：down 删容器（数据卷在 local/ 不丢，但
  容器名/网络要重建，回退窗口内没必要）；
- v2 大脑停机用 一键停止.bat（PID + 命令行双核验防误杀），**不 kill 协议端容器**。

## 5. 镜像行语义（O10 新行）

`docker-compose.yml` 的镜像行在停机后的语义不变，回退时**全部用本地已有镜像**，
不需要重新拉取：

| 镜像行 | 默认值（钉版本） | 语义 |
|---|---|---|
| `astrbot:` | `${ASTRBOT_IMAGE:-docker.io/soulter/astrbot:v4.28.2}` | 钉 v4.28.2 防面板密码机制漂移；`.env` 同名行可覆盖（国内镜像源前缀或降级版本号） |
| `heart:`（服务键，容器 vl-heart） | `${NAPCAT_IMAGE:-…napcat-docker:latest}` | 唯一跟随 latest 的常驻组服务；镜像行保持上游官方名（法律红线不中性化） |
| `etcd/minio/milvus:` | 各自 `:-` 默认钉版本 | legacy 组镜像行仅服务回退；日常 up/stop 不触碰 |

`.env` 的 5 行 `m.daocloud.io` 镜像源注释行（`.env.example`）只影响**拉取**通道；
回退窗口内镜像已在本地，`.env` 不动也能整组回退。

## 6. 回退后的数据边界（如实声明）

- **v2 期间的新对话**：落在 `local/vl_data/history.db`，并以 JSONL 双写镜像
  （同一轮对话同步追加写进另一个文件，供回退时并回旧库）存到
  `local/vl_data/mirror_v4.json`（回退合并源）。旧栈 `data_v4.db` 不会自动获得
  这些新对话——回退 = 接受"vl 期间她只记得回退点之前的事"，或按 mirror 镜像
  的行语义手工合并（user 先行、assistant 后补、弃轮无 assistant 行；见
  PERF_SPEC §7.1-2）。自动合并工具未实现，窗口内不做默认动作。
- **旧栈数据原位冻结**：`local/astrbot_data/`（含 `FROZEN` 标记文件——一个放在
  数据目录里写明冻结日期与"勿动"警示的标记，O14）与
  `local/milvus/volumes/` 在回退窗口内保持原样，只读不改；备份清单继续覆盖
  （增量≈0）。
- **README 口径**：vl 重启/回退期间 QQ 消息会丢（协议端在线但无人接），属预期，
  不是故障。

2. 摘除 compose 的 legacy 组与 `.env` 镜像变量行；
3. 从备份脚本清单摘掉 astrbot_data / milvus 卷行；
